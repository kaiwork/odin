## TL;DR

Web accessibility (often abbreviated "a11y") means building sites so that people with disabilities — and people in temporarily limiting situations — can actually use them. It is the framing lesson for the whole accessibility section: what the term covers, who it helps, and why it should be a default habit rather than an afterthought.

## Key concepts

### What accessibility is

Designing and building websites so that as few barriers as possible stand between the content and the person using it, regardless of how that person perceives, operates, or understands the web. Assistive technologies (screen readers, switch devices, magnifiers) can only do their job if the site gives them something to work with.

### Who it covers

Disabilities span several broad categories, and each can be permanent or temporary:

- **Visual** — blindness, low vision, colour-vision deficiency.
- **Auditory** — deafness or hearing loss (think captions for video).
- **Physical / motor** — limited fine motor control; mouse use may be impossible.
- **Cognitive** — conditions affecting memory, attention, or comprehension.

### Situational limitations

Accessibility features also help people who are not disabled but are constrained by circumstance: a phone screen in bright sunlight, browsing one-handed while carrying something, a slow or capped connection. This is a key argument for a11y — the audience is far larger than it first appears.

### The kerb-cut/elevator idea

Physical infrastructure offers the analogy: an elevator or ramp is built for wheelchair users but ends up helping people with strollers, luggage, or injuries. Accessible web features work the same way — captions help commuters on a loud train, good contrast helps everyone outdoors, keyboard support helps power users.

### Why start now

Accessibility is much cheaper to build in from the start than to retrofit. Perfect accessibility is not the bar; small, consistent improvements (semantic markup, labelled inputs, sufficient contrast) already remove real barriers.

## Common pitfalls

- Treating accessibility as a niche concern for a tiny user group — between disabilities, ageing users, and situational limits, it affects a large share of any audience.
- Deferring a11y to "polish later" — retrofitting is harder and it usually never happens.
- Assuming accessibility only means supporting screen readers — motor, auditory, and cognitive needs matter just as much.
